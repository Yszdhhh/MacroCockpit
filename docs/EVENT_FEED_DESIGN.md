# 设计提案：一事一卡的新闻流

状态：一事一卡事件流（`backend/event_feed.py`、`GET /api/v2/events`、首页「事件卡 / 逐条快讯」双轨切换、时间线展开与离线回放 `python -m backend.event_feed --replay`）已审查落地并保留原「逐条快讯」回退入口；事件推送默认保持关闭（仅落盘去重门禁），待双周并跑观察后按需启用。

## 我们定下的体验

首页按**事件**读，不按媒体帖子读。同一件事只有一张卡：先看到目前结论、核实状态和「最新变化」，展开再看时间线和原始来源。最快的可信报道负责发现，第一手公告负责确认，后续来源负责补充事实。十家转述同一通讯社，不等于十份证据，也不刷新卡片、不重复推送。

「算法精选」按事件的重要性排序；「实时时间线」按最近一次实质更新倒序。两者继续共享板块、标的、方向等筛选。已读以最后看过的事件更新为准：新增独立来源不恢复未读，实质更新才可标为「有新进展」。保留逐条原始报道供查阅，不把事件摘要包装成已确认事实。

## 什么时候建卡、补充或推送

| 收到的材料 | 看板行为 | 通知 |
| --- | --- | --- |
| 首条可信报道，尚无当事方确认 | 建卡，标「未证实」，附原始出处 | 默认不即时推送；只有高影响且来源可靠时可发，标题明确写「未证实」 |
| 同稿转载、翻译、标题改写，或引用同一匿名来源 | 归入同一出处家族，保留来源链接，不加实质更新 | 不推送 |
| 独立采访或第二份证据，但没有新事实 | 增加独立印证，标「多方报道，待官方确认」；不等同正式确认 | 不因来源数增加而推送 |
| 新数字、生效日、范围、接任安排等可核实增量 | 加一条时间线，只摘要变化并附原始证据；数字保留单位、时段、口径和来源 | 只在变化实质影响事件判断时推送，小补充留在卡里 |
| 官方确认、否认或原始来源更正 | 更新同卡状态，保留旧说法并标明已更正；冲突暂不能解决就并列展示 | 重要事件状态改变可通知；如果先前推送过有误说法，更正应通知同一群读者 |

**假想例子（不是实时新闻）**：一家芯片公司高管被媒体报道将离职 → 创建「高管离任」卡，标未证实 → 三家媒体转载，不再推 → 公司正式确认并披露生效日，在原卡写一条确认更新 → 后续披露接任人，如没有改变原判断，只更新时间线。同日该公司公布出口限制导致订单调整是另一件事，即使标的相同也应分卡，可互相链接。相隔数月、涉及同一职位的另一次人事变动也不沿用原卡。

## 给实现者的约束

- **复用现有发现链路。** 当前 `backend/kazike_engine.py` 的 14 天聚类已经区分同一发生、同一故事的跟进和综述，并保留部分合并来源。把它当匹配线索，不把聚类代表条目当永久事件身份：补证据应在代表条目丢弃转载前完成。先支持少量信号明确的事件类型，如重大公司公告、央行决议和宏观发布，不改现有 `/api/v2/signals` 契约。
- **身份稳定、更新可重放。** 建议持久化事件 ID、实体、事件类型、发生期或公告标识；标的、主题或标题相似度只能用于找候选。置信度不足宁可待核对或先分开；误合并可拆分，保留来源和历史。记录来源原文发布时间、系统首次看见时间、事件发生或生效时间，别用快照刷新时间替代。历史补录不冒充刚发生的新闻。
- **区分出处和事实。** 证据保留规范链接、原始发布方、引用关系及受支持的事实；不把观点当证据。每次实质更新只记变化、新旧值、当时状态、出处。迟到旧报道不覆盖较新确认；互相矛盾的消息保留双方原文和核实状态，不用报道数量投票。推送按事件、实质更新及渠道去重；重试、重跑、数据源恢复不补发旧通知，重要更正例外。
- **只读权限不扩大。** 事件流沿用公共快照脱敏和原子发布方式。公共接口不输出个人持仓、私人评分、未公开原始文本或通知设置。影响持仓只作为私人通知的筛选，不写进公共事件数据。只辅助判断，不自动执行交易。
- **先观察再替换。** 用最近可用的公开历史样本离线重放，人工核对误合并、拆分、首次发现耗时、独立首发和新增事实贡献；建议先并行观察两周，再决定哪些重复源降频，保留出故障时的替补。先上线看板，不默认开启新通知，保留现有快讯入口作为回退。KOL 原帖与观点统计、免费数据源增补可单独评估，不塞进本次实现。

## 验收用例

1. 同一通讯社报道的转载、中英译文和重跑：一张卡，一个事实更新，最多一次该更新的推送。
2. 两个地址看似独立但都引用同一采访：两处链接、一个出处家族；真正的独立确认仍不冒充官方确认。
3. 同一事件新增一项有口径的数字：同卡只新增一条时间线；无足够影响时不推。随后正式否认或重要更正：保留原说法并明确更正，通知已收到误报的人。
4. 同标的两个独立事件、不同月份的同类宏观发布、同日混合综述：不误并；低置信匹配可留待核对。
5. 同批数据重放、先收到确认再收到早期传闻、来源掉线后恢复：事件 ID 不变、状态不倒退、不重发。移动端展开时间线不横向溢出，原始出处可点开。
